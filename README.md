# dsh-session-move

给 DSH 侧栏加一层**工作区文件夹（分组）**，并且能把**会话移动**到别的工作区 —— 前者只改侧栏怎么摆，后者会真的把会话搬过去。

> **English**: a plugin for [DeepSeek Harness](https://github.com/deepseek-ai) that adds a *virtual folder* layer above workspaces — folders nest, hold any number of workspaces (and sessions placed under them), and never touch the disk — and can *move a session into another workspace* by rewriting the session file's recorded working directory (byte-verified, with automatic rollback on failure).

## 它长什么样

- 侧栏「工作区」上面多出一层**文件夹**：能套娃、能装任意多个工作区，**磁盘上不会多出任何目录**；
- 会话可以从一个工作区**搬到另一个工作区**（真正改变它的工作目录，之后这条会话里的工具都在新目录下跑）；
- 会话也可以**只做侧栏归组**：放进某个文件夹里，工作目录一点都不动；
- 已归档/子代理等会话的显示规则跟官方完全一致。

## 它是怎么组成的

插件分两部分，这是 DSH 插件的常见形态，不是笔误：

| 部分 | 跑在哪 | 干什么 |
| --- | --- | --- |
| 后台部分（`lib/index.js` 等） | DSH 的本地服务进程 | 读会话文件、改工作目录、加一个本地接口 |
| 界面部分（`lib/client.js`） | 你看到的网页界面 | 侧栏那棵树、菜单项、移动弹窗 |

> 下文提到「**后台**」= DSH 本地的服务进程；「**界面**」= 网页里那部分。

## 安装

1. clone 或下载本仓库到任意目录；
2. 装进你的 DSH profile：`dsh plugin --profile <你的 profile> add <本目录>`（桌面版的 profile 由应用自己管，命令被拒绝的话，就在「插件」页里装，或手工把 `dsh-session-move` 加进该 profile `package.json` 的 `dsh.profile.bundles`）；
3. **完整退出 DSH 再打开**。改插件不是"刷新一下"就能生效的 —— 界面代码和后台服务都要重新加载（原因见下面「开发注意」第一条）。

## 用法

1. 会话行右边「…」→ **移动到工作区 / 文件夹…**；
2. 在弹窗里选目标：
   - 选一个**工作区** → 真的搬过去（会改这条会话的工作目录）；
   - 选一个**文件夹**里的「把会话放这里」→ 只让它在侧栏归到那个文件夹，工作目录不动；
   - 已经在文件夹里的会话，弹窗顶部会多一行「**移出文件夹**」把它放回工作区下面；
   - 也可以直接填一个**新目录**，会自动登记成新工作区；
3. 点「移动」完成。

同一条会话可以反复移动。已是目标工作区、会话正在运行、子代理会话、目标目录不存在等情况都会给出明确提示，不会改坏数据。

## 工作区文件夹（分组）

官方侧栏只有"工作区（目录）"这一层，本插件在它上面加了一层纯虚拟的**文件夹**：

- 侧栏右上「＋」→ **新增文件夹**：随便建，不用选本地目录；
- 文件夹可以**套文件夹**、可以放**任意多个工作区**；工作区不能当父级（不存在这种层级）；
- 工作区行的「…」→ **移入文件夹…** / **不放入文件夹（顶层）**；文件夹行的「…」有 新建子文件夹 / 重命名 / 移入其它文件夹 / 删除（删除只是解散，里面的东西上移到父层）；
- 「＋」→ **新增工作区（选择本地目录）** 仍是官方的选目录流程；文件夹行的「…」里也有 **新建工作区（选目录后放进这里）**，建完自动放进去；
- 展开状态记在浏览器本地（localStorage）：文件夹与工作区默认展开，点行即收/放；
- 会话可见性照搬官方规则：**已归档的会话默认隐藏**（工作区「…」→「显示已归档的会话」可切换，这个开关和官方 / 归档管理插件共用同一份状态）、子代理会话不显示、非当前选中项的空会话不显示；
- 没归入任何工作区的会话放在末尾的「未分组」组里（官方同款）；
- **会话也能直接放进文件夹**（只动侧栏分组）：会话「…」→ 移动到工作区 / 文件夹… → 在文件夹那一行点「把会话放这里」。放进去之后它只在文件夹下显示一次（不再重复出现在所属工作区里），想放回去就选「移出文件夹」。

界面实现要点：平台不允许第二个插件再声明官方侧栏已经声明过的子槽位，所以本插件**不新注册侧栏占用者**，而是像 dsh-im-connect 那样把官方侧栏组件就地包一层（渲染出错时自动回落到官方侧栏）。这样渲染器仍然把官方的那套参数交给这层，于是所有插件贡献的会话菜单项（置顶 / 重命名 / fork / 归档 / 删除 / 移动到工作区…）照常出现，官方动作（打开会话、新建会话、重命名 / 删除工作区、选目录）也全部沿用。

## 会话移动是怎么做到的

DSH 里"会话属于哪个工作区"是由**这条会话自己的工作目录**决定的：

- 挂载会话时，DSH 会拿会话文件里记录的工作目录和工作区路径比对，不一致就拒绝；
- 会话文件在磁盘上的位置也由这个工作目录推导，位置和记录对不上会被当成损坏的会话；
- 官方没有"移动会话"的接口。

本插件把这件事拆成两步，一次做完：

1. **改数据**：重写会话文件开头记录的 `cwd`，并把会话目录搬到新目录对应的项目目录下；正文逐字节保留，写完立刻自检，失败就回滚。
2. **重新挂载**：让 DSH 按磁盘现状重新读一遍这条会话，挂到目标工作区、从旧工作区摘掉，然后马上把它放掉（不会一直占着内存）。

移动**不需要重启 DSH**，也不需要手工改 `workspace.json`（归属由 DSH 自己保存）。

## 冷会话与"打开着"的会话

只要一条会话被**打开过**（在对话页看过、聊过），DSH 后台就会一直留着它的进程，并且握着这条会话文件的写入权 —— 官方没有提供关闭它的办法。所以：

- **没打开过的会话**：点一下立刻完成，不用重启；
- **打开着、但空闲的会话**：这时改不了它的文件，插件会把这次移动**记成待办**，下次 DSH 启动时（那时所有会话都是冷的）自动完成 —— 界面会提示「完全退出并重开 DSH 后自动完成」。待办记录在 `<DSH 数据目录>/storages/session-move-pending.json`，连续失败 3 次才放弃；
- **有回合正在跑的会话**：直接拒绝，先等它结束再移动。

## 本地接口

后台只加一个本地接口，不替换 DSH 的任何官方能力：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/dsh-session-move?sessionId=<id>` | 工作区列表 + 这条会话当前的归属 |
| POST | `/api/dsh-session-move` | `{ action: "move", sessionId, workspaceId 或 targetPath, title? }` |

写请求只接受本机同源调用（校验 `Origin`/`Host` 与 `Sec-Fetch-Site`）。

## 配置

`package.json` 的 `dsh.client` 声明界面部分的入口文件；`cordis.patch.yml` 只做一条 `insert`，不禁用官方任何入口。

```yaml
- insert:
    - id: dsh-session-move
      name: 'dsh-session-move'
```

## 开发注意（这几个坑都是实际踩过的）

- **改了界面部分的文件也要完整重启 DSH**：DSH 会给每个界面模块按文件内容生成一个版本号（并按 `immutable` 缓存），只刷新页面的话，页面会拿着旧版本号去取、被后台按规则拒绝 —— 现象可能是「插件加载失败」，甚至「应用无法启动」；
- **不要直接读没声明依赖的 `ctx.xxx`**：Cordis 里访问未声明的服务属性会直接抛异常，取可选服务请一律用 `ctx.get("xxx")`；
- **所有"注册类"调用都要自带 try/catch**（路由、快捷键、槽位注册）：界面部分初始化时抛错，DSH 会判定 `entry did not activate`，直接弹启动失败并提示禁用第三方插件；
- 同理，本插件对外注册的每一处都有兜底，最坏情况只是"这个插件功能不可用"，不会连累 DSH 启动。

## 已知边界

- 移动会**改变会话的工作目录**：之后这条会话里的工具调用都在新目录下，历史记录里的旧路径不会改写。
- 有回合正在跑的会话会被拒绝，先结束后再移动。
- 只处理官方的 JSONL 存储（`session-persistence-jsonl`，日志格式 v4）；其他后端会因 `locate()` 不可用而拒绝。
- 移动一条**已经归档**的会话是允许的（归档集合按 id 全局保存），但它在侧栏里仍然显示为归档。
- 恢复会话时 DSH 会追加一条 `session/end-seed` 事件，这是官方的恢复标记，不影响历史内容。

## 卸载

从 profile 的 `dsh.profile.bundles` 里删掉 `dsh-session-move`，再执行
`dsh plugin --profile <name> remove dsh-session-move`，然后完整重启 DSH。
